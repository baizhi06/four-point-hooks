# 从六个插口合并到四个

## 第 0 步：先量

```bash
# 数清每类插口各有几处（按你自己的命名改关键字）
grep -n "onGroupMessage\|onPrivateMessage\|wakeGate\|promptBlock\|stateKey\|afterSend" src/bridge.js | wc -l
```

量完再决定：少于 10 处，四个钩子装上就够了，不用搬家；多于 30 处，按下面五步走。

## 五步

1. **装空钩子**：把 `src/hooks.js` 复制进去，四个位置各加一行调用，先不注册任何扩展。跑一遍你的基线（`verify.mjs` 之类），确认「行为一模一样」。
2. **合并消息入口**：群消息、私聊消息两个回调改成调 `onIncoming({ kind })`，原来的逻辑包一层 `if (kind === 'group')`。
3. **抽决策闸门**：把原来散在各处的「要不要醒」判断收进一个 `gate` 扩展，日志里打一行 `[hooks] gate/xxx 拦下`。
4. **抽上下文块**：提示词块逐个搬到 `context` 扩展，搬一块跑一次对照（提示词字数、结构），不对就回滚这一块。
5. **最后动手**：`clean` 放发送前清理，`afterSend` 放记账；这两个最容易出错，放在最后。

## 八条坑

| # | 坑 | 后果 | 怎么办 |
| --- | --- | --- | --- |
| 1 | 一次搬完所有块 | 提示词变了查不出是谁 | 一次只搬一块，搬完对照字数 |
| 2 | 读文件的扩展忘了 `cache: true` | 提示词缓存一直命中旧内容 | 读文件/DB/时间的一律声明 |
| 3 | 把限流放进钩子 | 某个扩展抛错 → 刷屏 | 限流、审计、脱敏留在主干发送函数 |
| 4 | 顺序靠 import 顺序 | 改一行 import 就悄悄变行为 | 每个扩展显式 `order` |
| 5 | 钩子里改消息内容 | 换个人加了钩子就串味 | `incoming` 只观察，不许改 |
| 6 | 忘了失败隔离 | 一个扩展崩 → 整个桥接停 | 每处 try/catch，只打日志 |
| 7 | 顺手把路由也塞进钩子 | 装配点又变多 | 路由并进 `onIncoming` 的分发里 |
| 8 | 搬完不写登记表 | 三个月后没人知道谁排第几 | `node verify.mjs --write-doc` |
