# four-point-hooks —— 给插件留四个口子

> 不是框架，不是运行时，不是依赖。**一个文件复制进项目，主干上留四个位置，功能全在别的文件里长。**
>
> 零依赖、纯 ESM、Node 18+、MIT。

很多插件都是同一条路走过来的：一开始用内联补丁加功能，加到后来变成

- 决策入口十几处（新消息、补唤醒、定时器、重试、主动机会各走各的）；
- 发送出口几十处，每处自己限流、自己脱敏；
- 提示词块七个函数，硬编码在一行 `return [a, b, c]` 里；
- 生成之后没有出口，清理逻辑散在几处。

结果是：加一个功能要动主干，升级上游要手工合并，三个月后没人说得清谁改了什么。

这个包只做一件事：**装配点收成四个，功能接口不设上限。**

> 只想要开关面板？跳到 [面板](#面板开关看得见)——三行代码接上，看登记表、拨开关、看实时计数。不想装也完全能用，核心只有 `src/hooks.js` 一个文件。

---

## 一眼看懂

| 症状 | 没有装配点时 | 装上以后 |
|---|---|---|
| 加功能要动主干 | 十几处插点，每处自己 try/catch | 在功能自己的文件里 `add()` 一行，主干不动 |
| 升级上游要手工合并 | 补丁散在几万行里，函数名全部绑定 | 主干只剩四个位置，其余都是模块 |
| 三个月后没人知道谁改了什么 | 靠记忆和 `git log` 考古 | 登记表：装配点 / 注册者 / 读写 / 是否影响缓存 / 顺序 |
| 想临时关掉一个功能 | 改代码、重启 | 面板上拨一下 |

---

## 这不是框架（先说清楚边界）

| 它做 | 它不做 |
|---|---|
| 提供四个固定位置，谁都能挂上去 | 不接管你的主流程 |
| 记录谁注册了什么、顺序、读写 | 不提供路由、不提供数据库、不提供 UI 框架 |
| 扩展坏了只打一行日志 | 不做依赖、不做构建、不做编译 |

一句话：**它只在你已经有的主干上，加四个调用点。**

---

## 四层：装配点就是四层

| 层 | 装配点 | 职责 | 什么时候调 |
|---|---|---|---|
| 接入层 | `onIncoming(ctx)` | 消息进来了（群 / 私聊用 `ctx.kind` 区分） | 收到消息后 |
| 决策层 | `gate(ctx)` | 要不要醒、要不要回 | 判断唤醒前 |
| 上下文层 | `context(key, extra)` / `stateKey(key)` | 提示词里塞什么；影响不影响缓存 | 组装提示词时 |
| 回执层 | `beforeSend(key, text)` / `afterSend(ctx)` | 发之前改正文，发之后记账 | 发送前后 |

回执层只有一个孔：`beforeSend` 是它的前半步，`afterSend` 是后半步。**不是两个孔。**

六个旧入口合并成这四个的对应关系，见 [从六处合并到四处](#从六处合并到四处)。

## 装进去（两种场景都只有四行）

**不要当依赖引。**把这个文件复制进项目（例如 `src/hooks.js`），在主干四个位置各加一行：

```js
import { onIncoming, gate, context, beforeSend, afterSend, stateKey } from './hooks.js';

// ① 接入层：消息进来
onIncoming({ key, kind, userId, text });

// ② 决策层：要不要醒
if (gate({ key, reason }).allow === false) return;

// ③ 上下文层：拼提示词
const blocks = context(key);                  // 字符串数组，按顺序拼
const cacheKey = `prompt:${stateKey(key)}`;   // 声明了缓存的扩展会让缓存键变化

// ④ 回执层：发送前后（同一个孔的两个半步）
const out = beforeSend(key, replyText);        // 截断 / 去重 / 脱敏
await deliver(key, out);                       // 你自己的发送函数
afterSend({ key, text: out, ok: true });       // 记账 / 捕获待办
```

> 本库是同步的：`gate()` / `beforeSend()` 直接返回结果，不用 await。主干是 async 也没问题，`await` 一个普通值不会出错。反过来要小心：**你自己的清理函数如果是 async 却忘了 await，闸门会永远拿到 Promise——等于没装，而且不报错。**

功能则在别处注册：

```js
import { add } from './hooks.js';

add('gate', 'quiet', (ctx) => isQuiet(ctx.key) ? { allow: false, reason: '静音中' } : { allow: true },
    { order: 10, note: '静音表命中就不唤醒' });

add('context', 'memory', () => readMemory(), {
  order: 10, cache: true, stateKey: () => String(mtime()),  // 读文件就必须声明，否则缓存读到旧内容
  note: '按会话记忆卡',
});
```

完整示例见 [`examples/extensions.mjs`](examples/extensions.mjs)。

## 接到别人的项目上

别人的项目里函数名、目录、状态文件都不一样，所以接入只按**位置**找，不按名字找：

| 找什么 | 怎么认 |
|---|---|
| 接入层 | 「收到一条消息」之后的第一个函数。群和私聊通常分两个入口，合并成一个 |
| 决策层 | 「要不要叫醒 / 要不要回复」的那个判断。返回真值就继续，返回假值就跳过 |
| 上下文层 | 组装系统提示词的那段：有几个块被拼成一个字符串 |
| 回执层 | 真正发出去的那个调用。前一行是清理，后一行是记账 |

接的时候**先只接接入层和决策层**（只读，不改行为），跑一周确认没问题，再接上下文层和回执层。每一步都能单独回退。

## 面板：开关看得见

装配点不该只活在日志里。`panel/server.mjs` 是单页面板，零依赖、零构建：

```js
import * as kit from './src/hooks.js';
import { createPanel } from './panel/server.mjs';

createPanel({ kit, title: '我的插件', configPath: './hooks.switches.json' })
  .listen(3131, '127.0.0.1');
```

打开 `http://127.0.0.1:3131/`，一页看到：

| 列 | 说明 |
|---|---|
| 装配点 / 注册者 | 例如 `context / memory` |
| 读写 | 只读 = 看一眼；改写 = 会改提示词或消息 |
| 缓存 | 声明了 `cache:true` 的，改了会让缓存失效 |
| 顺序 / 调用 / 错误 | `order`；实时次数；红字是最后一次错误 |
| 开关 | 点一下立刻生效，不用重启，写进开关文件 |

顶栏另有：总扩展数、开启 / 关闭、调用总数、错误总数、**缓存指纹**（`stateKey()` 当前值）。

三个接口，机器也能读：

| 接口 | 用途 |
|---|---|
| `GET /api/state` | 登记表 + 计数 + 缓存指纹（JSON） |
| `GET /api/hooks.md` | 同一张表的 Markdown |
| `POST /api/toggle` | `{"key":"clean/trim","enabled":false}`，只认登记表里已有的键 |

单独看效果：`node panel/server.mjs --demo`（默认 `127.0.0.1:3131`，挂四个示例扩展）。

> 安全边界：默认只绑 `127.0.0.1`；只写开关文件里的一个白名单键（`switches`）；不提供读源码、改配置正文、执行命令的接口。

---

> **两个前提保证**：① 旧装配点名（`clean` / `afterSend`）只兼容到 **0.3.0**，之后移除；② 一个扩展都不注册时，四个函数就是原样透传——`beforeSend` 连空白都不动，等于没装。

## 四条硬规矩

1. **失败隔离**：一个扩展抛错只打一行日志，不拖垮主流程。
2. **保命层不进插口**：限流、审计、凭证脱敏、去重留在主干唯一的发送函数里——这些要是能被插件改，出事就没人兜底。
3. **影响缓存必须声明**：读会变的东西（文件、数据库、时间）就 `cache: true` 并给 `stateKey`，否则提示词缓存会一直命中旧内容。
4. **一个功能一个口子**：同一个地方出现第三次内联，就该收成模块，而不是复制第三遍。

## 人工审核（写给用 AI 改代码的人）

改完必须有人读一遍，再提交。具体三条：

- **AI 产出的 diff 要自己看**：不看就提交，等于把不认识的内容塞进仓库；
- **改完写一行变更记录**：改了什么、为什么、怎么回滚；
- **提交前跑 `npm run verify`**：语法 + 单测 + 面板冒烟 + 登记表，全绿再推。

这三条不是形式——它们决定三个月后接手的你（或别人）能不能看懂。

## 从六处合并到四处

如果你现在的插件是六处插口，合并规则（**这段就是「删了哪些、并进哪儿」的账**）：

| 原来的六处 | 合并到 | 怎么并的 |
|---|---|---|
| 群消息 + 私聊消息 | `onIncoming` | 两个入口合一，用 `ctx.kind` 区分 |
| 唤醒闸门 | `gate` | 原样独立，不改语义 |
| 提示词块 + 状态键 | `context` + `stateKey()` | 同一扩展的两种能力：返回值是块，`stateKey` 是缓存指纹 |
| 生成后清理（transform） | `outbound` 前半步 | 和「发送前清理」合成一处，代码只跑一遍 |
| 发送后回调 | `outbound` 后半步 | 仍在这个孔里，只是阶段不同 |

合计：**六处入口 → 四处能力，其中「清理」和「记账」是同一个孔的前半步和后半步。**

没有删功能，只有合并位置——这一点要写清楚，否则就是悄悄丢东西。

顺序：先量（数清每类几处）→ 合两个消息入口 → 抽 `gate` → 抽 `context` → 最后并 `outbound`（先并清理，再并回调）。每步单独可回滚。

细节见 [`docs/MIGRATION.md`](docs/MIGRATION.md)。

## 验收线：怎么证明「只加后端，没改框架」

接完线，对主干文件跑 `git diff`，只允许出现两类改动：

| 允许 | 不允许 |
|---|---|
| 新增一行调用点（`gate(...)` / `beforeSend(...)` 这种） | 改动原来的判断逻辑 |
| 新增一个 import | 替换导出、套壳改写已有函数 |

套壳（运行时替换导出）看起来「主干一行没动」，但上游一旦改成内部直接调用，你那层就永远不触发——**功能悄悄死掉，日志一个错都不报。**

留调用点是显式的：上游一动，diff 里就能看见这个点需要重接。

## 三条「别抄」

- **别把装配接口也做成插件**：功能接口越多越好接，装配接口越少越好维护——这两句混在一起就会打架。
- **别整份打别人的补丁**：别人的补丁长在单个部署实例上，函数名和状态路径都不一样。
- **别急着上可视化**：先有登记表，再加开关；星图和 3D 留给业务面板，接口层不需要。
